# 大航海时代 1（繁体中文 DOS 版）研究笔记

逆向分析的结论汇总。所有地址都针对下面这一版文件；其他版本（日文版、英文版 Uncharted Waters、其他中文版）的地址和编码都不一样，不能直接套用，但方法可以参考。

## 1. 适用版本

| 文件 | SHA-256 |
|---|---|

| `MAIN.EXE`（脱壳后） | `41892a8133888452b71f273f6f6bc6974d6d5a177d53e54e85b289b1896f8629` |
| `ALLHAN.16P` | `831542db7083d2ce0e05b430ff7eca473cdf56d0c3e23ed0e9880d8b942394aa` |
| `NAME.16P` | `80f7e3d3477e7a71fc9dce3134291baec93a3adcf8fc691d33007ef16f34bb54` |

启动流程：`KOEI.COM` 依次运行 `FMDRV.COM`（音乐驱动）、`OPEN.EXE`（片头）、`MAIN.EXE`（游戏本体）、`END.EXE`（结局）。开局密码画面直接按回车即可进入。

## 2. 加壳与脱壳

- `MAIN.EXE` 用 **TINYPROG** 压缩：MZ 头偏移 0x1C 处有 `tz` 标记，入口是多层解压程序，每层先用 CRC 表解密下一层再跳过去。静态分析（Ghidra、Hopper）只能看到解压程序，看不到游戏代码。
- `OPEN.EXE`、`END.EXE` 用 **EXEPACK** 压缩（文件里有 `Packed file` 字样），本项目没有改它们。
- **脱壳方法**（`patcher/emu86.py`）：
  1. 写一个极简 8086 模拟器，只实现解压程序用到的指令和少量 DOS 中断；
  2. 运行到解压程序远跳回载入段（真正的入口 `CS:5204`）时停下，导出内存；
  3. 用两个不同的载入段（PSP = 0FF0 和 1FF0）各跑一次，两份内存里相差 0x1000 的字就是重定位项，一共 7619 个；
  4. 重新拼成普通 MZ 文件。入口 `0000:5204`，`SS:SP = 515A:0800`。
- 脱壳后的 `MAIN.EXE` 可以直接替代原版运行。修改文本、换字形都需要在脱壳版上进行。

## 3. 内存布局

- 编译器是 **Microsoft C 5.x**（数据段偏移 8 处是 `MS Run-Time Library - Copyright (c) 1988, Microsoft Corp`）。
- **数据段（DGROUP）** = 载入段 + 0x45B0。下文的"地址"都是数据段内的偏移。
- **代码** 在 DOSBox 的模拟内存里就位于"数据段起点 − 0x45B00"，所以找到数据段就能定位任何代码。下文的"代码偏移"都是相对载入映像起点的偏移。
- 在 DOSBox 里定位数据段：同时匹配偏移 8 处的运行库签名，和偏移 0x20F4 处的爵位名指针表 `d91fda1fdf1fe41f…`（只有 MAIN.EXE 有）。

## 4. 字库

| 字库 | 格式 | 用途 |
|---|---|---|
| `ALLHAN.16P` | 1249 条记录，每条 30 字节 = Big5 码（2 字节）+ 16×14 点阵（28 字节，每行 2 字节，高位在左）。字的顺序是游戏文本里首次出现的顺序。 | 菜单、对话、商品名等几乎所有文字 |
| `NAME.16P` | 10001 个 16×14 点阵，没有编码头。按笔画排序：Big5 常用字和部分次常用字按笔画合并排列。 | 起名字时选字 |
| 程序内置 | 代码偏移 0x3384 起，17 条 30 字节记录，格式同 ALLHAN，以 `FFFF` 结尾 | 开头密码画面（请输入正确密码、金木水火土日月天地人） |

原版点阵几乎都撑满 15×14 的字框（第 1–15 列、第 0–13 行）。新字形要按同样的框缩放，否则和原版字混排会大小不一。`patcher/render_glyphs.swift` 用"国、图、圆、回"几个满框字的墨迹范围作为基准框。

## 5. 文字编码

游戏文本不是 Big5，而是 2 字节代码（首字节 ≥ 0x92）混合 ASCII 和 ESC 控制序列（`ESC G` 换行、`ESC B`/`ESC C` 颜色、`ESC =yx` 光标定位）：

- 代码 = Big5 一级字的序号，按每行 188 个排列；
- 次字节跳过会和控制序列冲突的 ASCII 标点，有效次字节是 `0-9 A-Z a-z 0x80–0xFD`；
- 再加一个分段的固定偏移（约 −94），实现见 `patcher/koei_text.py`，对游戏文本解码准确率约 97%。

改词时只用游戏文本里已经出现过的字的代码，保证这些字在 ALLHAN 里有字形；替换前后长度相同，字符串不会错位。

## 8. 游戏机制（反编译确认）

- **国王召见**：海上航行时每天有 **5%** 概率检查（代码偏移 `B63F` 处的随机判断）；检查时若 **名望 > (爵位 + 1)² × 400**，就派国王任务，否则有一半概率派商人、行会的小委托。手上有任务时不派新任务。
- **王宫进门**：爵位为 0 时，只有被召见才能进；爵位 ≥ 1 随时能进。
- **任务类型**：爵位 0 固定派 0 号任务；之后任务号 = (爵位 − 1) ÷ 2 + 随机 0~1；爵位 9 固定派 4 号任务（营救公主）。
- **完成任务**：爵位 +1（最高 9），奖金 = (3 + 随机 0~2) × 爵位 × 1000，存入皇宫账户。
- **放弃任务**：名望减少当前值的 10%–20%。
- **发现港口**：航行时每走一步检查周围 8 格，有未发现的港口就提示并标记。奖励是给舰队里船长、航海士加经验值（(港口规模 + 1)² × 30），不加玩家名望。
- **补给消耗**：代码偏移 `36230` 的函数按船依次扣粮食和水。
- **炮击伤害**：代码偏移 `32301` 的函数，攻击方编号 ≤ 4 为玩家船；伤害扣目标的耐久、船员和两项属性。
- **白刃战**：代码偏移 `321BD` 的函数，按攻击方战斗力扣目标船员。

## 9. 存档 SAVE.DAT

- 文件 62596 字节。文件头里有 5 个档位的名字（偏移 5 起，每个 11 字节）。
- 第 N 个档位（N 从 1 开始）在文件偏移 `0x100 + (N − 1) × 0x3000`。档位前 0x1DB0 字节就是数据段 `0050–1DFF` 的原样快照，所以"文件偏移 = 0x100 + (N − 1) × 0x3000 + 地址 − 0x50"。
- **没有校验和**，直接改数值就能读档（已实测）。

## 10. 本项目用到的代码补丁

都在 DOSBox 内存里热改，关闭时写回原字节（`trainer/trainer.py` 里的 `CHEATS`）。

| 功能 | 代码偏移 | 原字节 → 新字节 | 原理 |
|---|---|---|---|
| 不消耗补给 | `36230` | `55` → `CB` | 扣补给函数直接 `retf` |
| 炮击一击必沉、敌方无伤 | `324A0` | 20 字节 | 原本"我方攻击伤害打八折"；改成按攻击方设伤害 255 或 0 |
| 白刃战一击清空 | `321E1` | 21 字节 | 我方攻击直接把目标船员设为 0；敌方攻击跳过扣减 |
| 召见检查每天一次 | `B63F` | `75 05` → `90 90` | 去掉 5% 随机判断 |
| 国王任务回去就完成 | `1A95D`、`1B3F0` | `74 0D` → `90 90`、`75 03` → `EB 03` | "已完成"不再要求完成标记；采购任务船上没货也继续判断（配合把 `1DF0` 清零、设上宝物标记） |
| 取消夜间不能战斗 | `3D1E7` | `72 1C` → `EB 1C` | 跳过时刻判断 |

`321E1` 那段里有一个远调用，它的段地址在 DOS 载入时会被改写，所以开启时要先保存内存里的原字节，关闭时原样写回。

## 11. 工具

- 反编译：Ghidra（16 位实模式）。Hopper 不支持 DOS MZ 格式。
- 反汇编：rizin。
- 模拟器：DOSBox-X（Homebrew）。读写它的内存要用 `task_for_pid`，需要管理员权限；DOSBox-X 只有临时签名、没有开启 hardened runtime，所以可以附加。
